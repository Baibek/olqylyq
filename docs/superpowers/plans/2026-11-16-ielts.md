# IELTS бағыты және топтарға бөлу — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an IELTS (English) subject to the adaptive diagnostic, a CEFR/band estimate, automatic level groups in the class view, and an English-teacher mode for Ұстаз-бот.

**Architecture:** IELTS is a fifth knowledge graph in `src/engine.js`, built by the existing `makeGraph` and run by the existing `Engine`. CEFR levels are stored in the topic `grade` field (A1=5 … C1=9) so scope logic is untouched; the page maps them to labels. Pure logic (`cefr`, `groupStudents`) lives in the engine and is tested with Node; UI is checked with a Playwright smoke script.

**Tech Stack:** Vanilla JS in one HTML page assembled by `build.py`; Node (vm) and Playwright (preinstalled, `require('playwright')`) for tests; Python 3 for the existing course check.

**Spec:** `docs/superpowers/specs/2026-11-16-ielts-design.md`

## Global Constraints

- Site stays one static `index.html` built by `python3 build.py`; never edit `index.html` by hand; no server, no new runtime dependency.
- Every new UI string exists in both `kk` and `ru`. Task content (sentences, options) is in English; instructions (stems) are `L(kk, ru)`.
- IELTS is added **next to** the four school subjects and is first in `SUBJ_KEYS` and the default subject.
- Listening and Speaking are out of scope; the band is shown as an approximate range with a note that it covers Grammar, Vocabulary, Reading and Writing skills only.
- Layout must work at 375 px width.
- After the final task, push to both `main` and `gh-pages`.

### Task 2: CEFR level, band estimate and grouping logic

**Files:**
- Modify: `src/engine.js` (add functions; export them in the `return { … }` of `CORE`)
- Modify: `tests/check_engine.mjs`

**Interfaces:**
- Produces: `CORE.cefr(G, res) -> { lvl: 4..9, label: 'A0'|'A1'|'A2'|'B1'|'B2'|'C1', band: string }`.
  Rule: walk levels 5→9; a level passes if ≥ 60 % of its topics have `res.st[id] === 'known'`; stop at the first failure; `lvl` = last passed level, or 4 if none. Labels/bands: 4 `A0` `<3`; 5 `A1` `3`; 6 `A2` `3.5–4`; 7 `B1` `4.5–5.5`; 8 `B2` `6–6.5`; 9 `C1` `7–8`.
- Produces: `CORE.groupStudents(G, list) -> [{ key, n, names: string[], topRoot: id|null }]`, `list = [{ name, res }]`. For `G.key === 'eng'` key = `cefr(G,res).label`; otherwise mastery `m = res.known / (res.known + res.gaps.length + res.unknown)` → `'low'` (< 0.5), `'mid'` (< 0.8), `'high'`. `topRoot` = most frequent `res.roots[0]` in the group (ties: first seen). Empty groups omitted; order: eng by level ascending, others `low, mid, high`.

- [ ] **Step 1: Add tests** to `tests/check_engine.mjs`:
  - `cefr(eng, simulate(eng, [], 1).result()).label === 'C1'` and `.band === '7–8'`.
  - `cefr(eng, simulate(eng, ['e1','e5'], 1).result()).label === 'A0'`.
  - `cefr(eng, simulate(eng, ['e16'], 1).result()).label` is `'A2'` or `'B1'` (gap starts at B1 grammar).
  - `groupStudents(math, [{name:'A',res:r1},{name:'B',res:r2},{name:'C',res:r3}])` where r1 = no gaps, r2/r3 = `simulate(math, ['n1'])` → keys `['low','high']`, low group `n === 2`, `topRoot === 'n1'`.
- [ ] **Step 2: Run** `node tests/check_engine.mjs` — Expected: FAIL (`cefr is not a function`).
- [ ] **Step 3: Implement** `cefr` and `groupStudents` in `src/engine.js` and export them.
- [ ] **Step 4: Run** `node tests/check_engine.mjs` — Expected: `problems: none`.
- [ ] **Step 5: Commit** `feat: CEFR estimate and student grouping`.
